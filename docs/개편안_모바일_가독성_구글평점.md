## 1. 근본 원인

### C1. 팝업이 시트 뒤 — 지도 중심 계산이 시트를 모른다
`src/components/MapView.tsx:316`

```js
map.setCenter(position);
```

지도 `<div>`는 `absolute inset-0` (칩바 아래 ~ 화면 바닥). 즉 **지도 좌표계의 중심 = 화면 y≈452**. 시트 상단은 y=379.8. 마커를 화면 중앙에 놓는 순간 그 자리는 이미 시트 아래다. 팝업(`bottom:48px`, 높이 171px)도 함께 묻힌다.

데스크톱에서는 안 보이는 버그다 — 패널이 왼쪽에 서기 때문. 모바일 전용 결함.

### C2. 당겨서 새로고침 — 오버스크롤을 막은 곳이 없다
`overscroll-behavior`가 프로젝트 전체에 한 줄도 없다(실측: html/body/리스트 전부 `auto`). 리스트 `scrollTop=0`에서 아래로 당기면 브라우저 새로고침이 그대로 걸린다.

동시에 **시트를 끌 수 있는 곳이 핸들 44px 하나뿐**이다(`ListPanel.tsx`의 `onPointerDown`). 리스트 본문을 잡고 올리면 아무 일도 없고, 놓고 다시 당기면 새로고침된다. 사용자가 겪은 순서가 정확히 이것이다.

### C3. 새로고침하면 위치를 잃는다 — URL에 지도 상태가 없다
`src/lib/url-state.ts`가 적는 것: `near, ll, r, cat, q, sort, open, min, place, all, discover`.
**지도 중심·줌이 없다.** 검색 없이 지도만 끌어서 본 상태는 URL에 흔적이 없으므로, 새로고침하면 초기 위치로 돌아간다. C2와 겹쳐서 "새로고침 → 처음부터 위치 찾기"가 된다.

### C4. 시트가 크롬(chrome)으로 꽉 찼다
핸들 44 + 헤더 64 + 툴바 162.8 = **271px이 고정 UI**, 내용은 111px. 툴바 4줄(검색 / 반경 / 액션 / 필터)은 전부 항상 펼쳐져 있고, 헤더는 브랜드 로고에 64px를 쓴다.

### C5. 카드가 172.9px로 두껍다
한 카드 안에 점수가 **두 번** 나온다 — `RatingRow`(N/K/G 3칸)와 그 아래 "통합 5.0" 줄. "자세히" 버튼도 카드 탭(=선택)과 기능이 겹친다. 이 마지막 줄 하나가 약 40px.

## 2. 모바일 가독성 개편

### P0 — 막힌 것 뚫기

**P0-1. 팝업을 보이는 지도 영역 한가운데로**
`MapView`에 `bottomInset` prop 추가(= 시트 높이). `App.tsx`가 스냅별 실제 높이를 내려준다.

```js
// setCenter 후, 보이는 영역(칩바 아래 ~ 시트 위) 기준으로 되민다
const visibleH = mapH - bottomInset;
map.setCenter(position);
map.panBy(0, (mapH - visibleH) / 2 * -1 + POPUP_LIFT);
```
- `POPUP_LIFT`: 팝업 높이 절반(≈86px)만큼 더 내려 마커+팝업이 함께 들어오게.
- 스냅이 바뀌면(`half`↔`full`) 선택된 곳이 있을 때만 다시 보정. 아니면 지도가 손가락 뗄 때마다 튄다(기존 주석 `MapView.tsx:334` 참고 — 같은 함정).
- `full`(92svh)에서는 지도가 사실상 안 보인다 → 선택 시 자동으로 `half`로 내린다.

**P0-2. 당겨서 새로고침 차단 — 1줄**
`src/index.css`:
```css
html, body { overscroll-behavior-y: none; }
```
리스트/시트 스크롤 컨테이너에는 `overscroll-contain` 유틸 추가(`PlaceList` `ul`, `PlaceSheet` 본문).

**P0-3. 시트 본문 어디서나 끌어올리기**
`ListPanel`의 드래그 시작을 핸들에서 시트 전체로 넓히되 규칙 하나: **스크롤 컨테이너가 최상단(`scrollTop===0`)이고 아래로 당길 때만 시트가 따라온다.** 그 외에는 평범한 스크롤. 표준 바텀시트 동작이고, P0-2와 합치면 새로고침 사고가 구조적으로 사라진다.

**P0-4. 지도 위치를 URL에 적는다**
`url-state.ts`에 `c=lat,lng` + `z=level` 추가. `onBoundsChange`에서 400ms 디바운스로 `replaceState`.
- 새로고침·뒤로가기·링크 공유 전부 같은 자리로 복원.
- `near`가 있으면 기존대로 `near/ll/r`가 우선(중복 복원 방지).

## 3. 구글 평점 — "저장할 방법"은 이미 있다. 파이프라인 3곳이 끊겨 있을 뿐

### 3.1 설계는 완성돼 있다
- `worker/index.js`: `GET /google` → KV 키 `g:all` 한 덩어리 반환. **이 경로는 구글 API를 절대 호출하지 않는다**(요금 0).
- `scripts/google-fill.mjs`: 원장(`raw/google.json`) 기준으로 받아 `raw/google-kv.json` 생성 → `wrangler kv bulk put`.
- `src/lib/worker.ts` `fetchGoogleAll()` + `App.tsx`가 `baseRatings`에 병합 → 목록·팝업·상세 전부에 구글 칸.
- 공개 `data/ratings.json`에는 안 넣는다(약관). 비공개 KV에만 둔다. **이 판단은 맞다.**

### 3.2 그런데 실제로는 이렇게 끊겨 있다 (실측)

| # | 지점 | 실측 결과 |
|---|---|---|
| ~~B1~~ | 라이브 번들 | **오판이었다. 아래 3.2b 참고** — 프런트는 정상이다 |
| **B2** | Worker | `GET /google` → `{"error":"empty"}` (400). `/google` 라우트가 없는 구버전이 떠 있다. **레포 어디에도 `wrangler deploy`가 없다**(`grep wrangler` = `kv bulk put` 두 줄뿐) |
| B3 | KV 데이터 | 원장 `raw/google.json` 부재 = `google-fill.mjs` 미실행(로컬 기준. CI 캐시에 남아 있을 수는 있다) |
| ~~B4~~ | 프론트 스위치 | **설정돼 있다. 아래 3.2b 참고** |

그래서 지금 카드의 G 칸은 **영구히 "수집 전"** 이다. 데이터가 없는 게 아니라 길이 끊겼다.

### 3.2b 정정 (2026-09-19) — B1·B4 는 내 검색이 틀린 것이었다

모바일 개편을 배포한 뒤 같은 검사를 다시 하며 드러났다. 라이브 번들에는 이렇게 들어 있다.

```js
const Nn = "https://matpin-ratings.e-hcg.workers.dev/", ji = !!Nn;   // GOOGLE_ENABLED
new URL("google", Nn.endsWith("/") ? Nn : `${Nn}/`)                  // fetchGoogleAll
```

- **`fetchGoogleAll` 은 있다.** 함수 이름은 minify 로 사라지고, 경로는 `new URL("google", base)` 라서 `/google` 이라는 문자열이 애초에 번들에 없다. 이름으로 찾은 게 잘못이었다.
- **`VITE_GOOGLE_RATINGS` 는 `1` 로 설정돼 있다.** `GOOGLE_ENABLED` 가 `!!RATINGS_API` 로 접힌 것이 그 증거다 — 값이 없었다면 `import.meta.env.VITE_GOOGLE_RATINGS === '1'` 가 `false` 로 접혀 식 전체가 `false` 가 됐을 것이다. `true && Boolean(x)` 라서 `!!x` 만 남았다.

어제 "라이브 카드에 G 칸이 서 있다"고 관측한 것도 이것과 어긋나지 않는다. 그때 브라우저는 Service Worker 가 캐시해 둔 옛 `index.html`(참조하던 JS 는 404)을 보고 있었다.

**그래서 막힌 곳은 B2 하나다.** 워커가 구버전이라 `/google` 이 400 을 준다 → `fetchGoogleAll` 이 빈 객체를 받는다 → `googleReady` 가 false → 구글 칸이 서지 않는다. **워커 배포 하나로 프런트는 그날 바로 켜진다** (KV 가 비어 있으면 칸은 서되 "수집 전"이므로, B3 도 같이 해야 숫자가 보인다).

**G4. KV 채우기 — 비용 계산**
구글 place ID 보유 **3,613곳** / 전체 4,084곳 (88.5%).

Place Details (Enterprise SKU): **월 1,000건 무료**, 초과 1,000건당 $20.

|---|---|---|

**G5. 30일 캐시 정책 — 알고 결정할 것**

구글 약관은 Places 콘텐츠 캐시를 30일로 제한한다(place ID·위경도는 예외). 현재 코드는:
- `worker/index.js`: `r:` 캐시 키는 TTL 30일로 맞춰 놨다 (정합)
- 그러나 `g:` 시드 키는 **TTL 없이 영구 저장**이고 (`index.js` 주석이 "TTL이 있으면 매달 3,613건을 다시 받아야 하고 그게 곧 요금"이라 명시), `google-refresh.yml`은 120일 주기다 → **30일 상한 초과**

선택지:
- (A) 규정대로 TTL 30일 → 매월 3,613건 필요 → 월 약 $52 고정
- (B) 현행 유지(120일) + 카드/상세에 **"구글 평점 · 수집일 YYYY-MM-DD"** 표기 → 오래된 값을 사용자가 알고 본다. 비용 $0(초기 1회 제외)
- (C) 구글 칸 포기, 네이버·카카오 2사 유지

개인용 비공개 앱이라는 점에서 **(B)** 가 현실적. 다만 이건 약관 리스크를 안다고 선택하는 것이지 준수는 아니다. 공개·상업 전환 시 (A)로 올려야 한다.

**G6. 표시**
`Ratings.google`에 `at`(수집 시각)이 이미 들어간다(`index.js`가 `{...r, at}`로 저장). `PlaceSheet`에 `구글 · 2026-09-19 기준` 한 줄, 90일 넘으면 흐리게. G5-(B)를 고르면 필수.

## A2. 파고 들어가 보니 원인이 하나 더 있었다

기획서의 C1(`map.setCenter`가 시트를 모른다)은 맞았지만, 그것만 고쳐도 팝업은 97px 남아 있었다. 실측으로 두 개가 더 나왔다.

**1) CustomOverlay 의 anchor 가 무력화돼 있었다 (진짜 주범)**
`yAnchor: 1`(아래쪽 끝 맞춤)로 만들었는데, 실제로는 `yAnchor: 0`처럼 동작해 팝업이 마커 **아래로** 174px 늘어졌다. 그 아래가 곧 시트다.

원인은 렌더 순서다. `CustomOverlay`는 `setMap` 하는 시점의 콘텐츠 **높이**로 기준점을 잡는데, 그 안은 React root 가 나중에 그린다 — 그 순간 div 높이는 0이다. 높이 0에 `yAnchor: 1`을 걸면 `yAnchor: 0`과 같은 결과가 된다. `xAnchor`도 같은 이유로 폭을 모른 채 계산돼 창이 마커 오른쪽에 붙었다.

→ anchor 를 0으로 두고 위치를 CSS `transform: translate(-50%, calc(-100% - 48px))` 에 맡겼다. CSS 는 자기 크기를 자기가 아니까 언제 그려지든 맞는다. `DiscoveredWindow` 오버레이도 같은 결함이라 함께 고쳤다.

**2) `map.panBy()` 가 같은 틱의 `setCenter` 뒤에서는 먹지 않는다**
디버그로 확인: `panBy` 호출 후에도 중심 좌표가 그대로였다. `getProjection().containerPointFromCoords()` → y 에 shift 를 더해 → `coordsFromContainerPoint()` 로 좌표를 직접 만들어 `setCenter` 하는 방식으로 바꿨다. 이건 실측으로 중심이 정확히 움직였다.

**3) 시트 드래그 종료 판정이 React 상태를 봤다**
`pointerup` 에서 상태(`drag.h`)로 이동량을 재니, 마지막 `pointermove` 가 반영되기 전이면 200px 플릭도 "안 움직였다"로 읽혀 탭(단계 순환)으로 처리됐다. 놓는 순간의 `e.clientY` 로 직접 계산하게 바꿨다.

## A5. 남은 것 · 알려진 한계

- **full 스냅(92svh)에서 팝업이 가려진다.** 지도에 남는 띠가 68px 뿐이다. 선택하는 순간에는 half 로 내리므로 실사용에서는 잘 안 만나지만, 선택한 뒤 직접 full 로 올리면 가려진다.
- **필터를 펼치면 리스트가 216px(카드 1장)로 줄어든다.** 사용자가 명시적으로 연 상태이고 접힘이 기억되므로 그대로 둔다.
- 랭킹 배지가 붙은 카드는 109.9px 보다 한 줄 더 길다.
- 지도 가장자리에서 고르면 팝업이 화면 밖으로 조금 나갈 수 있다(개편 전과 동일).
- 커밋·푸시는 하지 않았다.

## A6. 기획과 달라진 것

- **P0-3 을 축소했다.** 기획은 "목록 본문을 잡아도 시트가 따라온다(`scrollTop===0` 규칙)" 였는데, 그러려면 `touchmove` 를 `passive:false` 로 가로채야 하고 세로 스크롤과 경합한다. 대신 **손잡이 줄을 헤더와 합쳐 잡을 곳을 44px → 56px 로 넓히고 그 줄 전체를 탭·드래그 대상**으로 만들었다. 새로고침 사고 자체는 A1 의 `overscroll-behavior` 가 막으므로, 원래 문제(당기다 새로고침)는 해결된다.
- **P1-2 를 다르게 풀었다.** 헤더를 없애고 개수를 검색창 옆에 두는 대신, 헤더를 손잡이 줄 안으로 합쳤다(108px → 56px). 브랜드 배경색은 뺐다 — 64px 를 색으로만 쓰던 자리다.
- **P1-3 은 62 → 66svh.** 실측으로 카드 3장을 채우려면 62svh 로는 14px 이 모자랐다.
- **P2-3(구글 칸 폭)은 보류.** 구글 데이터가 아직 안 뜨므로 지금 다듬을 근거가 없다. 구글 기획에 넣는다.
