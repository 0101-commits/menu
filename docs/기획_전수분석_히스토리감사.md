## 4. 사용자 요청의 성격 (근거 기반 추론)

커밋 본문·기획서·결정표에 남은 사용자의 목소리를 근거로 요청 성격을 정리한다.

### C1. "믿을 만한 숫자" — 정확성이 기능보다 앞선다
- `기획_구글평점_확보와보관.md` §1-E: "이 앱의 존재 이유가 믿을 만한 숫자인데 그걸 스스로 무너뜨린다"(OCR 기각 근거).
- `9dc5944` 0점 교정, `71554b7` 오매칭 방지, README 평점 규칙(베이지안 보정)의 근거가 일관되게 "틀린 값은 없는 값보다 나쁘다".

### C2. "실측하라, 추정하지 말라"
- 세 기획서 모두 `## 0. 실측 (추정 아님)`으로 시작하고 px·건수·대비비를 직접 잰다. `2a6b92d`는 자기 진단을 정정("B1·B4는 내 검색이 틀린 것이었다").
- **의사결정 원칙**: 화면·라이브·curl로 재확인한 것만 사실로 인정. 이것이 이 팀의 최상위 규범이다.

### C3. "개인용이지만 약관·비용을 정면으로 본다"
- `기획_구글평점…` §0 F1~F9: 구글 약관을 조항 번호까지 인용하고 "30일이면 합법"이라는 자기 코드 주석의 전제를 스스로 반박. 결정표(§5)에서 "위험을 알고 고르는 것이지 준수가 아니다"라고 명시.
- 비용을 항상 수치로($52, 월 1,000 무료) 표로 비교.

### C4. "부채가 될 것은 만들지 않는다"
- README: "실행될 수 없는 워크플로는 부채이므로 만들지 않았다"(워커 CI 배포 부재의 근거). `725f6fd`: 크론이 막히자 코드는 남기되 두 줄로 되살릴 수 있게 정리.

### C5. "모바일에서 실제로 읽히는가"
- 단계 E 전체가 "half 스냅에서 카드 0.64장 → 3.2장"이라는 단일 수치를 목표로 삼음. 가독성을 정성이 아니라 "보이는 카드 수"로 정량화.

**요청의 큰 방향**: (1) 개인 즐겨찾기를 신뢰할 수 있는 비교 도구로, (2) 모바일 우선 가독성, (3) 무료·약관 한도 안에서 지속 가능하게, (4) 자동화하되 자동화가 조용히 틀리지 않게.

## 6. 개편/고도화/가독성 — 제안 (신규)

기존 3개 기획서가 이미 다룬 것은 재론하지 않고, 히스토리 전수 분석에서 새로 드러난 것만 제안한다. 각 항목에 근거 커밋/파일을 단다.

### 개편 (Rework)

**RW1. `useEffect` 의존성 감사를 회귀 게이트로 승격.**
R2가 4회 반복됐다(`31a5be0`#3#7, `ca828d0`#2). 지도UX 개편(`120c34e`)에서 effect가 더 늘었다. → MapView/PlaceList/App의 effect 목록과 deps를 문서화하고, 비동기 도착(ratings)·초기화 순서(map status)·정렬 변경 3종을 체크리스트로. **코드 수정 아님, 감사 산출물.**

**RW2. 부재 표현을 타입으로 강제.**
R1이 5회. `score`에 `null`(미제공)·`undefined`(미수집)·숫자를 섞어 판단이 흩어진다. → `types.ts`에서 `RatingValue = number | { absent: 'no-data' | 'not-collected' | 'unmatched' }` 같은 합타입 도입을 **다음 리팩터 후보로 기획**. 근거: `src/lib/rating.ts`, `RatingRow.tsx` 머리말의 "구분해 적는다" 원칙.

### 고도화 (Enhancement)

**EN1. 구글 롤링 갱신의 관측 가능성.**
`725f6fd`가 크론 대신 "본 순간 갱신"으로 우회했으나, `기획_지도UX…` 부록 A4가 "한 달 뒤 `at`이 실제로 갱신되는지 확인할 것"을 숙제로 남겼다. → 워커 `/health`에 `refreshedLast24h` 카운터 노출을 기획(값 유출 없음). 근거: `worker/index.js`, README `/health` 표.

**EN2. 매칭 신뢰도의 지속 측정.**
`google-verify-match`는 시드 전 1회 게이트(오류율 0%). 그러나 데이터는 봇이 계속 보강한다(단계 C 봇 6건). → 주간 50곳 표본 검증을 `enrich.yml`에 리포트로 추가하는 안. 근거: `.github/workflows/enrich.yml`, `reports/`.

### 가독성 (Readability)

**RD1. 남은 접근성 확인 항목 종결.**
`기획_지도UX…` §P2-4가 "고정 슬롯의 `✕` 44×44만 확인 필요"를 열어 뒀다. → 선택 카드 `✕`, 번호 마커 터치 타깃 실측. 근거: `PlaceCard.tsx`, `MapView.tsx`.

**RD2. 정렬 변경 시 번호 마커가 뛰는 문제.**
`기획_지도UX…` 부록 A4가 "며칠 써 보고 판단"으로 유보. → 정렬 전환 시 번호를 애니메이션/고정하는 안을 UX 결정 대기 항목으로 명문화. 근거: 상위 20 번호 마커 로직(`MapView.tsx`).

**RD3. 소스 코드 가독성 — App.tsx 비대.**
`src/App.tsx`가 39KB로 최대 파일이고 hotPaths 1위(11회 접근). effect·상태·URL 동기화·필터가 한 파일에 응집. → 필터 로직(`applyFilters`, `31a5be0`#8에서 이미 함수화)과 URL 동기화를 훅으로 분리하는 리팩터를 **기획만**. 근거: `.omc/project-memory.json` hotPaths, `App.tsx` 크기.
