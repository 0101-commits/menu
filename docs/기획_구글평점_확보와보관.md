# 구글 평점 — 어떻게 확보하고, 어떻게 보관할 것인가

작성 2026-09-19 · 대상 `0101-commits/menu` (맛핀) · 앞선 문서: `개편안_모바일_가독성_구글평점.md` §3

이 문서는 "구글 평점을 켜자"가 아니라 **"켜 두면 무엇이 풀려 있는가"** 를 먼저 센다.
현행 설계(3,613곳 전량을 KV에 영구 시드)는 켜지기만 하면 loose end 를 12개 남긴다.

---

## 0. 확정 사실 — 여기부터는 추측이 아니다

공식 문서·가격표·레포 실측으로 확인한 것만 적는다.

| # | 사실 | 출처 |
|---|---|---|
| F1 | **Place ID 는 무기한 저장해도 된다.** 캐싱 제한의 유일한 예외다 | Places 정책 |
| F2 | 그 밖의 Content 는 캐시 금지. 명시된 예외는 **위경도, 30일** 뿐이다 | Maps Platform 서비스 약관 3.2.3 |
| F3 | → **평점(`rating`)·리뷰 수는 30일 예외에도 안 들어간다.** "30일이면 괜찮다"는 우리 코드 주석의 전제가 틀렸다 | F2의 귀결 |
| F4 | `rating`·`userRatingCount`·`priceLevel`·`regularOpeningHours` 는 **전부 Place Details Enterprise SKU** | 데이터 필드 표 |
| F5 | Place Details Enterprise: **월 1,000건 무료**, 초과 $20.00/1,000 (0~10만 구간) | 가격표 |
| F6 | Place Details Pro 5,000 무료 / Essentials 10,000 무료 — 그러나 평점은 Enterprise 라 강등 불가 | 가격표 |
| F7 | Text Search(id·location·displayName) 는 별도 SKU, 월 5,000 무료 — **매칭에 이미 썼고 끝났다** | `scripts/match.mjs:17` |
| F8 | 귀속 표시 의무: **Google Maps 로고**, 공간이 없으면 **"Google Maps" 텍스트**. 가리거나 바꾸면 안 된다 | Places 정책 |

**F9 가 핵심이다.** 영구 보관이 허용된 유일한 자산은 이미 손에 있고, 공개 JSON 에 들어 있어 백업도 돼 있다. 남은 문제는 "그 ID 로 무엇을, 언제, 얼마나 오래 들고 있을 것인가" 뿐이다.

## 1. 확보하는 길 — 여섯 갈래

| | 방법 | 비용 | 약관 | 목록 전체 커버 | 판정 |
|---|---|---|---|---|---|
| **A** | Place Details 온디맨드 (본 것만) | 월 1,000 무료 안 | 캐시 기간만 쟁점 | 쓸수록 채워짐 | **채택** |
| **B** | 전량 시드 3,613곳 영구 (현행 설계) | 1회 약 $52 | F3 정면 충돌 | 첫날부터 100% | 폐기 |
| **C** | Places UI Kit 위젯 | SKU당 월 10,000 무료 | **보관 자체가 없음** | 상세 화면만 | 보조 채택 |
| **D** | 대체 출처(OSM·Overture·Foursquare OS) | 무료 | 문제없음 | — | **평점이 없다.** 기각 |
| **E** | 구글 지도 화면 캡처 → OCR | 사실상 0 | **스크래핑 금지 조항 정면 위반** | 이론상 100% | 기각 |
| **F** | 사람이 보고 직접 입력 | 0 | 사실의 수기 기록 | 비현실(3,613곳) | 부분 활용 |

### A — 본 것만 받는다
화면에 실제로 그려진 가게만 Place Details 를 부르고, 받은 값을 워커 KV 에 둔다.
처음에는 구글 칸이 거의 비어 있다가 쓸수록 채워진다. 그게 정확히 "실제로 보는 만큼만 돈과 보관을 쓴다" 는 뜻이다.

### C — UI Kit
구글이 자기 위젯으로 평점·영업상태·사진을 직접 그린다. 우리가 값을 받지 않으므로 **보관 논쟁 자체가 없고 귀속도 위젯이 알아서 한다.** 다만 우리 카드 디자인 안에 숫자로 끼워 넣을 수는 없어 **상세 시트 하단 보조 블록**까지가 한계다.

### E — 캡처·OCR 은 왜 기각인가
"API 를 안 쓰니 요금도 약관도 피한다"는 발상인데 반대다. 약관은 API 사용이 아니라 **Content 의 추출** 을 금한다 — 화면에서 긁는 쪽이 더 명시적인 위반이다. 게다가 3,613곳을 캡처하려면 지도 UI 자동 조작이 필요하고, DOM·레이아웃이 바뀌면 통째로 깨진다. 판독 오류가 나면 **틀린 평점을 맞는 것처럼 보여주는** 최악의 실패가 된다. 이 앱의 존재 이유가 "믿을 만한 숫자"인데 그걸 스스로 무너뜨린다. 만들지 않는다.

### F — 사람 입력은 어디에 쓰나
전량은 불가능하지만 **자주 가는 곳 20~50곳**은 현실적이다. A 가 채우기 전이라도 그곳만은 값이 선다. 소스를 `manual` 로 따로 표기해 구글 값과 섞지 않는다(그래야 F3 논쟁 밖에 있다).

## 2. Loose end 14가지

현행 설계를 그대로 켰을 때 풀려 있는 것들. **L1~L5 가 설계 결함, L6~L9 가 운영 공백, L10~L14 가 데이터 신뢰.**

### 설계

**L1. 평점은 30일 캐시 예외 대상이 아니다.**
`worker/index.js` 의 주석은 "구글 정책 상한 30일에 맞춘다"고 적었지만, 30일 예외는 위경도에만 있다(F2·F3). 그래서 `r:` 캐시(30일)도, `g:` 시드(무기한)도 같은 성격의 문제다. **정도의 차이지 종류의 차이가 아니다** — 이걸 인정하고 기간을 정해야지, 30일이면 합법이라고 믿고 넘어가면 안 된다.

**L2. `g:` 시드 키에 TTL 이 없다.**
```js
await env.RATINGS.put(`g:${g}`, JSON.stringify({ ...r, at: ... }));  // TTL 없음
```
주석이 이유를 솔직히 적어 뒀다 — "TTL 이 있으면 매달 3,613건을 다시 받아야 하고 그게 곧 요금이다." 비용이 보관 기간을 정하고 있다. 순서가 거꾸로다.

**L3. 목록용 집계에 수집 시각이 없다.**
`scripts/lib/google-aggregate.mjs` 는 `score`·`count`·`price` 만 담고 `at` 을 버린다.
그래서 목록에서는 **이 숫자가 어제 것인지 넉 달 전 것인지 알 방법이 없다.** 신선도 표기도, 기간 만료도, 감사도 전부 불가능하다. 상세를 열어 온디맨드로 다시 받은 값에만 `at` 이 있다.

**L4. 원장이 GitHub Actions 캐시에 산다 — 그리고 그 캐시는 크론보다 먼저 사라진다.**
```yaml
- uses: actions/cache/restore@v4
  with: { path: raw, restore-keys: google-ledger- }
- cron: '0 20 1 * *'      # 월 1회
```
Actions 캐시는 **7일간 접근이 없으면 축출**된다. 크론 간격은 30일이다. 즉 **매달 빈 원장으로 시작**한다.
`google-fill.mjs` 는 원장이 없으면 3,613곳 전부를 "한 번도 안 받은 것" 으로 보고 `--limit=1000` 만큼 앞에서부터 다시 받는다 → **매달 같은 1,000건에 돈을 쓰고, 나머지 2,613곳은 영원히 못 받는다.** `raw/` 는 `.gitignore` 에 있어 다른 사본도 없다.
이 하나만으로 B(전량 시드) 경로는 성립하지 않는다.

**L5. 집계 축소 방지 게이트가 없다.**
다른 데이터에는 이미 게이트가 있다(`800dffb` "축소 방지 게이트"). 그런데 `g:all` 은 원장이 비면 그대로 `{}` 가 되어 KV 에 덮인다 → **목록의 구글 칸이 통째로 사라진다.** L4 와 만나면 실제로 일어난다.

### 운영

**L6. 워커 배포 경로가 레포에 없다.**
`grep wrangler` 결과는 `kv bulk put` 두 줄뿐. `wrangler deploy` 가 없다. 그 결과가 지금 상태다 — 코드에는 `/google` 라우트가 있는데 배포본에는 없어서 `{"error":"empty"}` 400 을 준다. **지금 구글 칸이 안 뜨는 유일한 이유가 이것이다.**

**L7. 워커의 `GOOGLE_PLACES_KEY` 시크릿 설정 여부를 확인할 수 없다.**
```js
if (g && env.GOOGLE_PLACES_KEY) { ... }
```
없으면 온디맨드 경로가 **조용히** 꺼진다. 오류도 로그도 없다. 앱에서는 "수집 전" 과 구분되지 않는다.

**L8. 일일 한도 카운터가 원자적이지 않다.**
코드가 스스로 적어 뒀다 — KV 의 read-modify-write 는 원자적이지 않고 읽기 일관성도 최대 60초 지연이다. 동시 요청 N건이 함께 통과할 수 있다. **요금의 진짜 상한은 GCP 콘솔의 Place Details 일일 할당량**인데, 그게 실제로 걸려 있는지 확인된 바 없다.

**L9. 귀속 표시가 의무를 못 채운다.**
카드의 구글 칸은 파란 원에 `G` 한 글자다. 이건 Google Maps 로고도, "Google Maps" 텍스트도 아니다(F8). 자체 제작 마크는 오히려 "로고를 변형" 에 가깝다.

### 데이터 신뢰

**L10. 폐업 판정이 되돌아오지 않는다.**
`gone: true` 는 TTL 없이 영구 저장되고 이후 다시 묻지 않는다. 일시적 404·오류로 한 번 `gone` 이 박히면 그 가게의 구글 평점은 **영영 안 뜬다.**

**L11. 매칭 정확도를 표본으로 검증한 기록이 없다.**
3,613건이 Text Search 로 붙은 ID 다. 동명이인·체인점·인접 건물을 잘못 잡았을 때 결과는 "평점 없음" 이 아니라 **다른 가게의 평점을 이 가게 것으로 보여주는 것** 이다. 없는 것보다 나쁘다. 카카오는 92.2%, 구글은 73.4% 매칭이었다는 기록만 있고 **맞게 붙었는지** 는 안 쟀다.

**L12. 브라우저·CDN 캐시는 회수할 수 없다.**
`/google` 응답에 `cache-control: public, max-age=3600` 이 붙는다. 보관 기간을 어떻게 정하든 **이미 나간 1시간치는 우리가 지울 수 없다.** 기간 정책을 세울 때 이 층을 빠뜨리면 계산이 안 맞는다.

**L13. 원장 백업이 없다.** (L4 의 다른 얼굴)
`raw/` 는 gitignore. 유일한 사본이 7일짜리 CI 캐시다. 돈을 주고 받은 데이터인데 백업이 없다.

**L14. "월" 의 경계가 불분명하다.**
무료 한도는 월 단위인데 크론은 `0 20 1 * *`(매월 1일 20:00 UTC = 2일 05:00 KST) 다. 구글의 사용량 월 경계가 어느 시간대인지 확인하지 않았다. 월말·월초에 걸치면 한 달에 두 번 청구되는 실수가 난다.

## 3. 권고 설계 — "본 것만, 시각과 함께, 짧게"

L1~L5 는 전부 **전량 시드** 라는 한 가지 결정에서 파생됐다. 그걸 버리면 다섯이 한꺼번에 사라진다.

### 3.1 비용이 정말 문제인가 — 세어 보자

| 시나리오 | 월 Place Details 호출 | 무료(1,000) |
|---|---|---|
| 캐시 없이 목록 40장 × 하루 3세션 × 30일 | 3,600 | 초과 |
| **30일 캐시 + 실제 다니는 지역(고유 300~800곳)** | **300~800** | **안 넘음** |
| 전량 시드 1회 | 3,613 | $52 |

**캐시는 비용상 필수고, 30일이면 개인 사용량에서 무료 안에 들어온다.** 반대로 캐시를 없애면 약관은 깨끗해지지만 요금이 난다. 이건 맞바꿈이지 정답이 있는 문제가 아니다 — 그래서 §5 에서 사용자가 고르게 한다.

### 3.2 설계

```
목록·팝업 ─┐
           ├─→ 워커 /google?ids=...  (KV 에 "이미 있는 것" 만 돌려줌. 구글 API 안 부름)
상세 ──────┘        ↓ 없으면
                 화면에 실제로 그려진 카드에 한해 Place Details 1건씩
                 (하루 상한 + GCP 콘솔 하드캡)
                        ↓
                 KV `g:{placeId}` = { score, count, price, at }  TTL 30일
```

바뀌는 것:

1. **`g:all` 통짜 블롭 폐기** → `/google?ids=a,b,c` 로 **화면에 뜬 것만** 묻는다. 없는 것은 없다고 답한다. 이 경로는 지금처럼 구글 API 를 절대 부르지 않는다(요금 0).
2. **모든 값에 `at`(수집 시각) 을 함께 저장하고 함께 내려준다.** L3 해소. 집계 스키마에 `at` 추가.
3. **`g:` 키에 TTL 30일.** 시드가 없으니 "매달 3,613건 재수집" 부담도 없다. L2 해소.
4. **전량 시드·원장·`raw/google.json`·월간 크론 전부 폐기.** L4·L5·L13 이 존재 이유째 사라진다.
5. **목록 지연 로딩:** `PlaceList` 가 실제로 렌더한 카드(첫 40장)의 ID 만 모아 한 번에 묻는다. 스크롤로 늘어나면 추가분만.
6. **온디맨드 채움에 상한:** 한 화면에서 새로 받는 건수를 N개(예: 10)로 끊는다. 지도를 마구 밀어도 한 번에 40건이 나가지 않게.

### 3.3 화면

- 카드 구글 칸: `4.3` + 보조줄 `리뷰 1.2천` + **`· 3일 전`** (30일 가까워지면 흐리게)
- 아직 없는 곳: 지금처럼 `—` / `수집 전`
- 상세 시트: 하단에 **Google Maps 귀속 표시**(로고 또는 "Google Maps" 텍스트) + "Google 지도에서 보기" 딥링크. L9 해소.
- 보조로 **UI Kit `PlaceDetailsCompactElement`** 를 상세 시트에 넣는 안(§1-C). 이건 보관이 0이라 논쟁 밖이다.

### 3.4 운영

- `.github/workflows/worker-deploy.yml` 신설 — `worker/**`·`shared/**` 변경 시 `wrangler deploy`. **L6 해소이자 지금 막힌 것을 뚫는 한 수.**
- 워커에 `GOOGLE_PLACES_KEY` 유무를 알리는 진단 응답 추가(`/health` 에 `google: true|false`). L7 해소.
- **GCP 콘솔 > API 및 서비스 > 할당량**에서 Place Details 일일 한도를 직접 건다(예: 40/일). KV 카운터는 완충일 뿐. L8 해소.
- `gone` 은 TTL 90일로. 되살아난 가게를 다시 묻는다. L10 해소.
- `/google` 응답 `cache-control` 을 `max-age=600` 으로 줄이고 `private` 로. L12 완화.
- 매칭 표본 검증: 무작위 50곳을 뽑아 `googlePlaceId` 가 그 가게가 맞는지 눈으로 확인하고 결과를 문서에 적는다. 오류율이 5%를 넘으면 구글 칸을 켜지 않는다. **L11 은 켜기 전에 반드시 닫는다** — 틀린 평점은 없는 평점보다 나쁘다.

## 4. 순서

|---|---|---|---|

| 5 | 프런트: 화면에 뜬 것만 조회, 신선도 표기, Google 귀속 | L3·L9 | 반나절 |
| 6 | 전량 시드·원장·월간 크론 삭제 | L4·L5·L13·L14 | 1시간 |
| 7 | (선택) 상세 시트에 UI Kit 블록 | — | 반나절 |

3단계가 게이트다. 여기서 오류율이 높으면 4단계 이후를 하지 않는다.

## 5. 결정이 필요한 것

**D1. 보관 기간.** 세 갈래다.
- **(가) 30일 TTL** — 위경도 예외를 준용한 관례적 선. 개인 사용량이면 무료 안. **약관 문언을 엄밀히 읽으면 여전히 허용 범위 밖이다.** 위험을 알고 고르는 것이지 준수가 아니다.
- **(나) 24시간 TTL** — 훨씬 보수적. 같은 가게를 다른 날 보면 다시 부른다. 월 호출이 2~4배로 늘어 무료 한도를 넘길 수 있다.
- **(다) 보관 0, UI Kit 만** — 논쟁 자체가 없다. 대신 목록 카드에는 구글 숫자가 영영 안 들어가고 상세 시트의 위젯으로만 본다.

**D2. 전량 시드($52)를 정말 버릴 것인가.** 버리면 첫날 목록이 거의 빈다. 대신 L1~L5·L13·L14 가 함께 사라진다. 이 문서는 버리기를 권한다.

**D3. 매칭 오류율 허용선.** 3단계 표본 검증에서 몇 %까지 받아들일 것인가. 이 문서는 5%를 제안한다.

---

## 6. 안 하기로 한 것

- **화면 캡처·OCR 수집** — 약관의 스크래핑 금지 조항 정면 위반이고, 판독 오류가 곧 틀린 평점이다. 만들지 않는다.
- **대체 출처로 평점 대체** — OSM·Overture·Foursquare OS 데이터에는 별점이 없다. 카테고리·좌표는 이미 충분하다.
- **구글 평점을 공개 `data/ratings.json` 에 넣기** — 지금 판단이 맞다. 공개 레포에 올리는 순간 재배포 금지 조항까지 걸린다.
