**이 사실이 중요하다.** 국내 3사의 모바일 웹은 전부 앱 유도용이고, 지도↔목록은 **전환**이지 **공존**이 아니다. 맛핀의 바텀시트는 모바일 웹에서 3사보다 앞선 UX다 — 베낄 대상이 없으므로, 시트의 규칙은 아래 1.4 의 표준 가이드에서 가져온다.

### 1.4 표준 가이드 (문헌)

- **Material 3**: 스냅은 Closed → Half(0.5) → Expanded. 드래그 핸들은 드래그·탭 모두로 단계를 순환. 시트 안에 스크롤 콘텐츠가 있으면 "콘텐츠 스크롤 먼저, 시트 드래그는 핸들/헤더에서" ([M3 Bottom sheets](https://m3.material.io/components/bottom-sheets/guidelines))
- **Apple HIG**: detent 는 medium/large 두 단계, 그래버로 드래그 가능함을 알린다. Apple 지도가 대표 사례 ([HIG Sheets](https://developers.apple.com/design/human-interface-guidelines/components/presentation/sheets/))
- **NN/G**: 모바일에서 사용자는 지도보다 목록을 쉽게 쓴다. 숫자 클러스터 마커는 혼란을 준다 ([NN/G Maps and Location Finders](https://www.nngroup.com/articles/mobile-maps-locations/))
- **비모달 시트**: 지도 상세 시트는 스크림으로 지도를 막지 않아야 한다 ([NN/G Bottom Sheets](https://www.nngroup.com/articles/bottom-sheet/))
- **카카오 SDK 공식 샘플**: hover = 큰 마커 + 인포윈도우, click = 색 변경 + 이전 선택 복원 ([apis.map.kakao.com](https://apis.map.kakao.com/web/sample/multipleMarkerEvent2/))

문헌 조사 원본은 `.omc/research/mapux-literature.md`. 다만 그 문서의 "개인 즐겨찾기라 항목이 적을 것"이라는 전제는 **틀렸다 — 맛핀은 4,084곳이다.** 클러스터링·페이지네이션을 빼라는 권고는 그 전제 위에 있으므로 채택하지 않는다.

## 2. 진단 — 왜 그렇게 되는가

**D1. 목록은 선택을 모른다.**
`PlaceList` 가 받는 건 `selectedPlaceId` 뿐이고, 쓰는 곳은 카드 테두리 색 하나다(`PlaceCard` `selected`). 스크롤도, 순서도 건드리지 않는다. 40장 페이지네이션(O2)과 만나면 **선택한 가게가 DOM 에 없는 경우**까지 생긴다.

**D2. 한 화면에 같은 정보가 두 번 있다.**
지도 위 팝업(`PlaceInfoWindow`)과 목록 카드(`PlaceCard`)는 같은 것을 말한다 — 이름·카테고리·영업상태·3사 평점·통합 점수·자세히. 팝업은 그 대가로 지도의 174~219px 를 먹고, 그걸 피하려 `centerForPopup()` 이 투영 좌표를 직접 계산한다(O7). **정보 중복을 없애면 그 계산도 같이 없어진다.**

**D3. 상세까지 2탭이고, 뒤로가기로 못 닫는다.**
3사 PC 는 전부 마커 1클릭 = 상세다(1.1·1.2). 맛핀은 팝업 → 자세히. 게다가 히스토리가 안 쌓여(O5) 모바일에서 뒤로가기를 누르면 앱을 나간다.

**D4. 지도를 미는 순간 목록이 리셋된다.**
`scope='map'` 이 기본이라 지도 이동 → `visiblePlaces` 교체 → `PlaceList` 의 `places` 참조가 바뀜 → `limit=40` 초기화 + `scrollTop=0`(O3). 구글은 이 동작을 **기본으로 끄고 체크박스로 켜게** 한다(1.2). 맛핀은 끌 방법이 없다.

**D5. 목록 3번째가 지도 어디인지 알 수 없다.**
네이버는 번호로 잇는다(1.1). 맛핀 마커는 카테고리 색뿐이라 목록↔지도 대응이 눈에 안 보인다.

**D6. 구글 칸은 워커 배포 하나에 막혀 있다.**
코드에는 `/google` 라우트가 있는데 배포본에 없다(O6). 프런트는 정상이라는 것이 이미 확인됐다(`개편안_모바일_가독성_구글평점.md` §3.2b).

**D7. 목록용 구글 값에는 수집 시각이 없다.**
`toAggregate()` 가 `score`·`count`·`price` 만 담고 `at` 을 버린다(`scripts/lib/google-aggregate.mjs:18-22`). 목록의 구글 숫자가 어제 것인지 넉 달 전 것인지 화면이 알 방법이 없다.

**D8. 월 1회 전량 갱신 크론은 구조적으로 안 돈다.**
`google-refresh.yml` 은 원장을 **Actions 캐시**에서 복원하는데, Actions 캐시는 7일간 접근이 없으면 축출되고 크론 간격은 30일이다. 매달 빈 원장으로 시작해 **같은 앞쪽 1,000건에 반복 과금**하고 나머지는 영원히 못 받는다.

**D9. 3열이 되면 모바일 칸이 좁아진다.**
390px − 시트 패딩 24 − 카드 패딩 28 ≈ 338px, 3칸 + gap 16 → **칸당 약 107px**. `방문 9,764` 같은 보조 글자가 잘린다.

## 3. 개편안 — 사용자가 무엇을 느끼게 되는가

### P0. 지도와 목록을 잇는다 (이번 개편의 본체)

**P0-1. 핀을 누르면, 고른 가게가 목록 맨 위에 선다.**

화면 폭에 따라 다르게 푼다. 근거는 "보이는 카드 수"다.

| | 동작 | 왜 |
|---|---|---|
| 모바일 | 시트 목록 **맨 위 고정 슬롯(sticky)** 에 선택 카드를 띄운다. 스크롤과 무관하게 항상 그 자리 | 시트 본문이 370px = 카드 3장뿐이라 "스크롤해서 보여주기"로는 곧 다시 사라진다. 40장 밖의 가게도 띄울 수 있다(D1 해소) |
| 데스크톱 | 해당 카드로 **`scrollIntoView({block:'center'})` + 하이라이트**. 순서는 그대로 | 네이버·구글과 같은 방식. 화면이 넓어 순서 정보를 유지하는 편이 이득 |

고정 슬롯 카드에는 `✕`(선택 해제)를 둔다. 필터·범위 밖의 가게를 지도에서 고른 경우에도 이 슬롯은 뜬다 — "지도에 있는데 목록에 없다"가 사라진다.

**P0-2. 팝업을 없애고, 선택 카드 하나로 합친다 (모바일).**

지금: 마커 탭 → 지도 위 팝업(219px) + 목록 어딘가의 카드.
바꿈: 마커 탭 → **마커만 커지고 이름 라벨이 뜬다** + **시트 상단 고정 슬롯에 선택 카드**.

- 구글 지도 모바일 앱이 쓰는 구조와 같다(핀 강조 + 하단 카드).
- 지도 가림이 219px → 0 이 된다. 시트를 `peek`(96px)로 내리면 지도가 거의 전부 보인다.
- `centerForPopup()` 의 투영 좌표 보정(`MapView.tsx:175-196`)과 스냅 변경 시 재보정 effect 가 **통째로 사라진다.** 마커를 "보이는 띠의 한가운데"에 놓기만 하면 된다.
- 데스크톱은 팝업을 유지한다(지도가 넓고 시트가 없다). 실제로 데스크톱에서는 팝업이 가려진 적이 없다.

**P0-3. 데스크톱은 마커 1클릭 = 상세.**

네이버·구글 PC 와 같게 한다(1.1·1.2). 상세는 지금처럼 `PlaceSheet` 를 쓰되 **목록 패널 오른쪽에 나란히** 연다(리스트 유지). 모바일은 1탭=선택 카드, **선택 카드 탭 = 상세**(2탭)를 유지한다 — 좁은 화면에서 1탭 즉시 전체화면 상세는 지도 탐색을 끊는다(NN/G 의 "목록이 쉽다"는 관찰과 별개로, 지도에서 고른 직후 위치 맥락을 잃는 것이 더 큰 손실이다).

**P0-4. 뒤로가기로 상세가 닫힌다.**

- `detailPlace` 가 생길 때만 `writeUrl(..., 'push')`, 나머지는 지금처럼 `replace`(주석이 이미 그렇게 적혀 있다 — 코드가 안 따랐을 뿐).
- `popstate` 리스너를 달아 URL 의 `place` 가 사라지면 상세를 닫고, 있으면 연다.
- 모바일 시트 스냅도 같은 규칙: 상세(full) → 뒤로 → 목록(half).

### P1. 지도를 밀어도 보던 자리를 잃지 않는다

**P1-1. 같은 결과면 목록을 리셋하지 않는다.**
`PlaceList` 의 리셋 effect 를 `places` 참조가 아니라 **내용 서명**(정렬된 `placeId` 조인 또는 `length + 첫/끝 id`)으로 건다. 지도를 조금 밀어 결과가 같으면 스크롤도 `limit` 도 그대로다(D4 완화).

**P1-2. `지도 이동 시 목록 갱신` 토글.**
구글의 체크박스 그대로. 끄면 지도를 아무리 밀어도 목록이 고정되고, 지도 위에 **`이 지역에서 다시 찾기`** 버튼이 뜬다(네이버·구글 공통 패턴). 상태는 `localStorage` + URL(`follow=0`).
기본값은 **켬** — 지금 동작이고, 끄는 걸 기본으로 하면 처음 쓰는 사람이 "목록이 안 바뀐다"고 느낀다.

**P1-3. 정렬 상위 20개에 번호를 붙인다.**
네이버식 번호 매칭(1.1). 전량(4,084)이 아니라 **현재 목록 상위 20개만** 번호 마커로 바꾼다 — 그 이상은 지도가 숫자로 뒤덮인다(NN/G 의 숫자 클러스터 경고와 같은 이유). 카드 좌측에도 같은 번호. 21번째부터는 지금의 색 핀.

### P2. 마무리

- **P2-1. 클러스터 탭 = 그 범위로 확대**(zoom-to-bounds). 현재 클러스터러 기본 동작을 명시적으로 건다.
- **P2-2. 선택 상태 3종을 눈으로 구분**: 기본 핀 / hover(데스크톱, 살짝 확대 + 이름) / 선택(큰 핀 + 라벨 + z-index). 카카오 SDK 공식 샘플 그대로.
- **P2-3. 지도 빈 곳 탭 = 반경 내 목록**(`nearby`, 최대 12곳)은 **유지**한다. 3사에 없는 맛핀 고유 기능이고, 핀이 겹친 곳에서 실제로 유용하다.
- **P2-4. 접근성**: 터치 타겟 44×44 이상, 카드 간격 8px 이상(문헌 §4). 현재 카드 높이 109.9px 는 충족, 고정 슬롯의 `✕` 만 확인 필요.

## 4. 구글 3열 — 확보 · 보관 · 갱신

사용자 질문 그대로 답한다.

> **"한 번 조회되면 구글 평점을 저장해 두고 나중에 불러올 수 있나? 한 달에 한 번 갱신하는 방향은?"**
> **된다. 그 코드는 이미 있다**(`worker/index.js` 의 `g:{placeId}` 쓰기). 그리고 **"30일 TTL + 본 것만 채움"이 곧 "한 달에 한 번 갱신"이다** — 크론 없이 같은 결과를 얻는다. 반대로 **크론으로 전량을 매달 갱신하는 길은 못 쓴다**(D8, 그리고 매달 $52).

### 4.1 설계

```
목록·선택 카드 ─┐
                ├─→ 워커 GET /google?ids=a,b,c   (KV 에 있는 것만 반환. 구글 API 안 부름 = 요금 0)
상세 ───────────┘            ↓ 없는 것은
                     화면에 실제로 그려진 카드만 Place Details 1건씩
                     (하루 상한 + GCP 콘솔 일일 할당량)
                            ↓
                     KV  g:{placeId} = { score, count, price, at }   TTL 30일
```

바뀌는 것:

1. **`g:all` 통짜 블롭 폐기 → `/google?ids=` .** 지금 라우트는 KV 키 하나를 통째로 주는데, 그 키를 채우는 길(전량 시드)이 D8 로 막혀 있다. 화면에 뜬 40장의 ID 만 물으면 시드가 필요 없다.
2. **`at`(수집 시각)을 저장하고 함께 내려준다.** D7 해소. 카드 보조줄에 `· 3일 전`, 25일이 넘으면 흐리게.
3. **`g:` 키에 TTL 30일.** 30일 뒤 자동으로 빠지고, 다시 보면 그때 다시 받는다 = 월 1회 갱신.
4. **전량 시드·원장·`raw/google.json`·`google-refresh.yml` 폐기.** D8 이 존재 이유째 사라진다.
5. **목록은 지연 로딩.** 렌더된 카드의 ID 만 모아 한 번에 묻고, 스크롤로 늘면 추가분만.
6. **한 화면에서 새로 받는 건수 상한 10건.** 지도를 마구 밀어도 한 번에 40건이 나가지 않는다.

### 4.2 비용 — 실제로 무료 안에 들어오는가

Place Details(Enterprise SKU: `rating`·`userRatingCount`·`priceLevel`)는 **월 1,000건 무료, 초과 1,000건당 $20**.

| 시나리오 | 월 호출 | 판정 |
|---|---|---|
| 캐시 없이 목록 40장 × 하루 3세션 × 30일 | 3,600 | 초과 ($52) |
| **30일 캐시 + 실제 다니는 지역(고유 300~800곳)** | **300~800** | **무료 안** |
| 전량 시드 3,613곳 1회 | 3,613 | $52, 그리고 TTL 30일이면 매달 반복 |

**첫날에는 구글 칸이 대부분 빈다.** 그게 이 설계의 값이다 — 쓰는 만큼만 채워진다. 2주 굴려 보고 커버리지(본 가게 중 구글 값이 선 비율)를 재서, 낮으면 그때 시드를 다시 논한다.

### 4.3 화면

- 카드 3열: `4.3` + 보조줄 `리뷰 1.2천 · 3일 전`
- 아직 없는 곳: `—` / `수집 전` (지금 규칙 그대로. `미매칭`·`리뷰 없음`·`수집 전`을 구분하는 현행 문구는 좋다)
- **모바일 칸 폭 107px 대응(D9)**: 보조 글자를 `리뷰 1.2천`(이미 `formatCount` 존재)으로, `· 3일 전`은 **상세에서만**. 칸이 좁으면 점수만 남기고 표본은 두 번째 줄로 줄바꿈하지 말고 잘라낸다(칸 수 불변 원칙 유지).
- **귀속 표시**: 지금 카드의 파란 원 `G` 는 Google Maps 로고도 "Google Maps" 텍스트도 아니다. 상세 시트 하단에 **`Google Maps` 텍스트 + Google 지도 딥링크**를 둔다(구글 PC 가 워터마크를 화면에서 뺀 적이 없다 — 1.2).

### 4.4 켜기 전에 반드시 닫을 것 — 매칭 표본 검증

구글 매칭은 Text Search 로 붙인 3,613건이고, **맞게 붙었는지 잰 적이 없다.** 틀리면 결과는 "평점 없음"이 아니라 **다른 가게의 평점을 이 가게 것으로 보여주는 것**이다. 없는 것보다 나쁘다.

→ 무작위 50곳을 뽑아 `googlePlaceId` 가 그 가게가 맞는지 눈으로 확인하고 결과를 문서에 적는다. **오류율 5% 초과면 3열을 켜지 않는다.**

## 6. 완료 기준

- 지도에서 아무 핀이나 누르면 **그 가게가 목록 맨 위(모바일) 또는 화면 가운데(데스크톱)에 보인다.** 41번째 이후여도, 필터 밖이어도.

- 상세를 열고 **뒤로가기를 누르면 목록으로 돌아온다**(앱을 나가지 않는다).
- 지도를 밀었다 놓아도 목록 스크롤 위치가 유지된다(결과가 같을 때).
- 데스크톱에서 마커 1클릭에 상세가 뜨고 리스트가 남아 있다.
- 카드·선택 카드·상세 세 곳 모두 **구글 평점이 실제 숫자**로 보이고, 그 옆에 수집 시점이 적혀 있다.
- 구글 매칭 표본 50곳 검증 결과가 문서에 적혀 있고 오류율이 5% 이하다.

### 7.1 구현하며 바뀐 것 — 갱신은 크론이 아니라 "본 순간"

계획은 워커 Cron Trigger(매일 03:30 KST, 오래된 것부터 33건)였다. 배포에서 거절됐다.

```
This account has reached the Workers Free limit of 5 cron triggers per account. [code: 10072]
```

워커 코드는 올라갔고 트리거만 실패한다. 다른 워커(AI_CLI·economic-site 등)가 이미 다섯 칸을 쓰고 있다.
**그래서 갱신을 `/google?ids=` 응답 경로에 붙였다** — 돌려준 값 중 `at` 이 30일보다 낡은 것을 골라,
한 요청에 최대 5건까지 뒤에서(`ctx.waitUntil`) 다시 받는다. 하루 상한(`DAILY_GOOGLE_LIMIT=30`)을
온디맨드와 함께 나눠 쓴다.

오히려 이쪽이 낫다.
- 아무도 안 보는 가게를 갱신하느라 무료 한도를 쓰지 않는다. **보는 것만 신선하다.**
- 낡은 값도 화면에는 즉시 나온다(그 자리에서 기다리지 않는다). 다음에 볼 때 새 값이다.
- `scheduled` 핸들러는 코드에 남겨 뒀다. 유료 전환이나 다른 워커의 크론 한 칸이 비면 `wrangler.toml` 의 두 줄만 살리면 된다.

## A3. 기획과 달라진 것

- **갱신 방식.** 크론이 막혀(무료 5개 한도) "본 순간 갱신"으로 바꿨다. §7.1 참고.

- **데스크톱 팝업.** 상세 패널이 열려 있으면 지도 팝업을 닫는다. 1클릭에 둘 다 뜨면 같은 내용이 두 번 나오고 지도만 가린다.

## A4. 남은 것

- 구글 값이 30일을 넘기면 그 가게를 **볼 때** 갱신된다(한 요청당 최대 5건, 하루 30건). 한 달 뒤 `at` 이 실제로 갱신되는지 한 번 확인할 것.
- `sync-myplace.yml` 최근 실행이 실패로 남아 있다(이번 개편과 무관, 별건).
- 상위 20 번호는 정렬 기준(거리/평점/리뷰)에 따라 바뀐다. 정렬을 바꿀 때 번호가 뛰는 것이 혼란스러운지는 며칠 써 보고 판단.
